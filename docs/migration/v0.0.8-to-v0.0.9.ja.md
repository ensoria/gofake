# gofake v0.0.8 から v0.0.9 への移行

[English](v0.0.8-to-v0.0.9.md) · [変更履歴](../../CHANGELOG.md)

## Go と依存モジュールを更新する

必要な Go のバージョンが 1.24.2 から **1.26.4** に上がります。開発環境・CI・Docker のビルドイメージを更新してください。利用側モジュールの `go.mod` にも Go 1.26.4 以上が必要です。v0.0.9 のタグ公開後、利用側のモジュールルートで実行します。

```sh
go version
go get github.com/ensoria/gofake@v0.0.9
```

## フィールド参照をメソッド呼び出しに変更する

v0.0.8 の呼び出し例

```go
n := f.Rand.Num.IntBt(1, 10)
p := f.Person
name := p.Name()
```

v0.0.9 の呼び出し例

```go
n := f.Num().IntBt(1, 10)
p := f.Person()
name := p.Name()
```

| v0.0.8 | v0.0.9 |
| --- | --- |
| `f.Rand.Bool` | `f.Bool()` |
| `f.Rand.Num` | `f.Num()` |
| `f.Rand.Str` | `f.Str()` |
| `f.Rand.Time` | `f.Time()` |
| `f.Rand.Slice` | `f.Slice()` |
| `f.Rand.Map` | `f.Map()` |
| `f.Person` | `f.Person()` |
| `f.Color` | `f.Color()` |
| `f.Address` | `f.Address()` |
| `f.Barcode` | `f.Barcode()` |
| `f.Company` | `f.Company()` |
| `f.File` | `f.File()` |
| `f.Image` | `f.Image()` |
| `f.Internet` | `f.Internet()` |
| `f.Lorem` | `f.Lorem()` |
| `f.Medical` | `f.Medical()` |
| `f.Payment` | `f.Payment()` |
| `f.PhoneNumber` | `f.PhoneNumber()` |
| `f.UserAgent` | `f.UserAgent()` |

コンストラクタが 19 個の生成器を初期化し、同じアクセサを繰り返し呼ぶと同じポインタを返します。メソッドを連続して呼ぶ箇所のほか、代入やコールバックも確認してください。たとえば `var x any = f.Person` は今もコンパイルできますが、格納されるのは `func() *person.Person` 型のメソッド値です。生成器を保存するには `f.Person()` を使います。

## Faker を保持・構築するコードを更新する

- フィールドを指定した `faker.Faker{…}` や生成器フィールドへの代入はコンストラクタに置き換えます。シードを固定する場合は `faker.CreateWithSeed(seed)` または `faker.CreateWithLocaleAndSeed(locale, seed)` を使います。初期化済みの Faker をコピーすると生成器のポインタを共有します。独立した乱数列が必要ならもう一度コンストラクタを呼びます。
- `math/rand` の任意の `*rand.Rand` を使う場合は `r := core.NewRand(source)` を呼びます。得られた `r` では `r.Num.IntBt(1, 10)` などのフィールド参照を引き続き使えます。`person.New(r, locale)` などのコンストラクタに同じ `r` を渡すと乱数列を共有できます。`core` と `generator/person` の import パスは `github.com/ensoria/gofake/pkg/faker/` 配下です。
- アクセサはポインタレシーバーです。アクセサを要求するインターフェースには `*faker.Faker` を渡します。`map[string]faker.Faker` の要素や `faker.Faker` 型の関数の戻り値は、ローカル変数に代入して呼ぶか、ポインタで保持してください。encli の `Seed(faker.Faker)` では、引数 `f` に対してそのまま `f.Person().Name()` を呼べます。
- リフレクションやシリアライズで Faker の公開フィールドを読んでいる場合は、必要な生成結果を持つ構造体を定義します。

## 未対応データの扱いを更新する

- `Company().EIN()` は接頭辞があるロケールで米国の EIN 書式の合成値を返します。未対応時は空文字を返し、ロガー設定時は警告を 1 件出します。以前の `-1234567` のような値を期待するテストを更新してください。この場合は乱数を消費しなくなったため、同じ Faker で**その後に生成する値**を固定シードで比較していれば、期待値も確認します。
- `Person().MaleKanaName()`、`FemaleKanaName()`、`KanaName()` は、未対応時に空文字を返し、ロガー設定時は警告を 1 件出します。従来はふりがな用コールバックがないと panic する場合がありました。片方だけに対応するカスタムロケールでは、その個別メソッドを使います。`KanaName()` には両方の設定が必要です。

## 利用プロジェクトと encli で確認する

```sh
go mod tidy
go test ./...
```

Ensoria で新ロケールを使う場合は、対応版の encli バイナリの公開後にバイナリを更新し、`encli seed` を実行するプロジェクトの gofake も更新します。seed ランナーのビルドには利用側の依存関係を使います。encli モジュールの更新で gofake の選択版も上がることがあるため、`go list -m github.com/ensoria/gofake github.com/ensoria/encli` で両方のバージョンを確認してください。Seeder を実行し、利用側の呼び出し順で固定シードの期待値も確認します。
