# gofake v0.0.9 実装計画

**目的**　`Faker` の生成器へのアクセスを統一し、5 ロケールを追加する。今回のリリース作業に encli の更新を含め、利用側プロジェクトで `encli seed --locale` から 5 ロケールすべてを選択して seed を実行できるようにする。README を日英に分け、v0.0.8 の利用者向けに移行手順を公開する。

**実装順**　gofake の API → ロケール → 公開ドキュメント → encli のランナー → ensoria-template の利用箇所 → 3 モジュールの結合検証。公開順は gofake → encli → ensoria-template。各段階で下記のコマンドを対象モジュールのルートから実行する。

**レビュー**　第 1〜6 節をそれぞれ 1 つの Phase とする。各 Phase の検証後に作業を止め、変更箇所、レビューのポイント、実装中に気づいた点を共有する。レビューで了承を得てから次の Phase に進む。

**技術**　Go 1.26.4 以上、Ginkgo v2 / Gomega、Cobra、`text/template`、結合検証用の一時 SQLite DB。各モジュールの既存の依存を使う。ソースとコメントは公開情報だけで理解できるようにする。

## 1. Faker の生成器アクセサ

v0.0.8 の `Faker` では `f.Rand` と 13 個のカテゴリが公開フィールドになっている。`f.Rand` の再代入後は、そこから取得する生成器と初期化済みのカテゴリが異なる乱数源を参照し得る。

### 公開 API

4 コンストラクタ `Create() *Faker`、`CreateWithLocale(*provider.Localized) *Faker`、`CreateWithSeed(int64) *Faker`、`CreateWithLocaleAndSeed(*provider.Localized, int64) *Faker` を維持する。全アクセサは `*Faker` のメソッドとし、同じインスタンスからは生成器の同一ポインタを返す。取得で生成器の再作成や乱数の消費が発生しない。呼び出し例は `f.Num().IntBt(1, 10)` と `f.Barcode().EAN13()`。[Effective Go のゲッター](https://go.dev/doc/effective_go#Getters)

| メソッド | 戻り値 |
| --- | --- |
| `Bool()`、`Num()`、`Str()`、`Time()`、`Slice()`、`Map()` | 順に `*core.RandBool`、`*core.RandNum`、`*core.RandStr`、`*core.RandTime`、`*core.RandSlice`、`*core.RandMap` |
| `Person()`、`Color()`、`Address()`、`Barcode()`、`Company()` | 順に `*person.Person`、`*color.Color`、`*address.Address`、`*barcode.Barcode`、`*company.Company` |
| `File()`、`Image()`、`Internet()`、`Lorem()`、`Medical()` | 順に `*file.File`、`*image.Image`、`*internet.Internet`、`*lorem.Lorem`、`*medical.Medical` |
| `Payment()`、`PhoneNumber()`、`UserAgent()` | 順に `*payment.Payment`、`*phonenumber.PhoneNumber`、`*useragent.UserAgent` |

`newFaker` で受け取った共通の `*core.Rand` を非公開の `rand` に保ち、カテゴリの既存生成器も非公開フィールドに保持する。コアの 6 アクセサは `f.rand` の既存フィールドを返す。`Faker.Rand` を削除し、利用者はコンストラクタで作成する。独立した乱数源やカスタムの生成器構成が必要な利用者には、公開済みの `core.NewRand(*rand.Rand)` と各生成器の `New` を案内する。`core.Rand` 自体のフィールド構成はそのまま使う。返される生成器は共有ポインタで、読み取り専用や並行利用を保証する API ではない。

## 2. 追加ロケールとデータの範囲

追加するコードは `de_DE`、`en_GB`、`fr_FR`、`en_CA`、`en_IN`。Go 公式の 2025 Developer Survey の居住国設問（3,453 件）で、既存対応の米国に続くドイツ 11%、英国・フランス各 5%、カナダ・インド各 4% を選んだ。割合は丸め値で、回答分布は北米・欧州寄り。カナダとインドでは英語表記を対象とし、別言語はロケールを分けて扱う。[Go 公式調査](https://go.dev/blog/survey2025)・[居住国グラフ](https://go.dev/blog/survey2025/location.svg)

### 共通の提供項目

`pkg/faker/provider/locale/<locale>/` に `constructor.go`、`people.go`、`addresses.go`、`companies.go`、`phonenumbers.go` を置く。公開エントリーポイントは `New() *provider.Localized`。4 つのデータポインタを初期化する。既存構造に従い、テンプレートと対になる `Create...` コールバックを設定する。コールバックは既存の生成器メソッドを必要な分だけ呼び、ロケールから生成器パッケージへの import は避ける。

- **人名**　男性名、女性名、姓、およびそれらを使う `MaleName()`、`FemaleName()`、`Name()`。ドイツ語とフランス語はアクセント等を含む実用的な綴りを収録する。インドはラテン文字表記とする。
- **住所**　`City()`、`Street()`、`StreetAddress()`、`Postcode()`、`Address()` を全ロケールで提供する。各ロケールが持つ都市名・通り名・番地の組み合わせを使う。カナダは `State()` と `StateAbbr()`、ドイツとインドは `State()` も提供する。都市・州・郵便番号は書式に沿う合成データで、地理的な対応や配達可能性は保証しない。
- **会社**　現地の組織形態を含む `Name()` と、該当言語の `JobTitle()` を提供する。ふりがなや EIN 用のデータは追加しない。既存のグローバル生成器には手を加えない。`PhoneNumber().E164PhoneNumber()` は引き続きグローバルのデータを参照する。ロケール別の国内電話番号は `PhoneNumber().PhoneNumber()` で取得する。

### 書式の受け入れ条件

表の `#` は数字、`%` は 1〜9、空白は半角スペース。`en_GB` と `en_CA` は各 2 種以上のマスクを用意し、アルファベット位置に許可された大文字をリテラルで書く。`AlphaDigitsLike` の `?` は小文字も返す。表の例は採用可能なマスクで、全地域・全書式の網羅は要件に含めない。

| コード | 住所・郵便番号 | 国内電話番号の生成範囲 |
| --- | --- | --- |
| `de_DE` | `通り名 番地\n郵便番号 都市`、郵便番号は 5 桁（`#####`）。 | Bundesnetzagentur の固定電話用フィクション帯。初期マスクは `030 23125###` と `040 66969###`。 |
| `en_GB` | `番地 通り名\n都市\n郵便番号`。郵便番号の外向き・内向きコードをスペースで分ける（例 `SW#A #AA`、`M## #BB`）。 | Ofcom のフィクション帯。初期マスクは `020 7946 0###` と `07700 900###`。 |
| `fr_FR` | `番地 通り名\n郵便番号 都市`、郵便番号は 5 桁（`#####`）。 | Arcep の映像作品用番号。初期マスクは `01 99 00 ## ##` と `06 39 98 ## ##`。 |
| `en_CA` | `番地 通り名\n都市 州・準州略号  郵便番号`（郵便番号の前は空白 2 つ）。郵便番号は `A1A 1A1` 型（例 `M%B #A#`、`V#B #A#`）。 | カナダの市外局番を使い、`555-0100`〜`555-0199` に限定する。初期マスクは `416-555-01##` と `604-555-01##`。 |
| `en_IN` | `番地 通り名\n都市 州 PIN`。PIN は 0 で始まらない 6 桁（`%#####`）。 | 先頭が `6`、`7`、`8`、`9` のいずれかの 10 桁。桁の区切りは `10`、`5-5`、`4-3-3` の 3 種で、区切り文字は半角スペース。例 `6123456789`、`61234 56789`、`6123 456 789`。 |

住所資料は [UPU ドイツ](https://www.upu.int/UPU/media/upu/PostalEntitiesFiles/addressingUnit/deuEn.pdf)、[UPU 英国](https://www.upu.int/UPU/media/upu/PostalEntitiesFiles/addressingUnit/gbrEn.pdf)、[UPU フランス](https://www.upu.int/UPU/media/upu/PostalEntitiesFiles/addressingUnit/fraEn.pdf)、[Canada Post の郵便番号](https://www.canadapost-postescanada.ca/cpc/en/support/articles/addressing-guidelines/postal-codes.page)、[Canada Post の住所表記](https://www.canadapost-postescanada.ca/cpc/en/support/articles/addressing-guidelines/important-information.page)、[UPU インド](https://www.upu.int/UPU/media/upu/PostalEntitiesFiles/addressingUnit/indEn.pdf)。番号の参照先は [Bundesnetzagentur](https://bundesnetzagentur.de/DE/Fachthemen/Telekommunikation/Nummerierung/DramaNumbers/artikel.html)、[Ofcom](https://www.ofcom.org.uk/phones-and-broadband/phone-numbers/numbers-for-drama)、[Arcep の番号計画 §2.5.12](https://www.arcep.fr/uploads/tx_gsavis/25-2215.pdf#page=54)、[Canadian Numbering Administrator](https://www.cnac.ca/other_codes/555/555_line_numbers.htm)、[TRAI の携帯番号資料](https://www.trai.gov.in/sites/default/files/2024-08/PR_No.34of2020.pdf)。

### en_IN の国内電話番号

`pkg/faker/provider/locale/en_IN/phonenumbers.go` の `CreatePhoneNumbers() *provider.PhoneNumbers` は、4 種の先頭数字と 3 種の区切りを組み合わせた 12 通りのマスクを 1 件ずつ返す。既存の電話番号生成器がマスクをランダムに選び、残り 9 桁を数字で埋める。番号形式を模したテストデータであり、利用可能性や実在番号との重複回避は保証の対象外。予約番号帯に限定する要件が生じた場合の確認事項は [後続メモ](en-in-domestic-phone-numbers.md) に置く。

- [x] `en_IN/phonenumbers_test.go` で既存の電話番号生成器から得た出力の先頭・桁数・空白位置を検査し、固定シードで 12 通りすべてが出ることを確認した。
- [ ] `en_IN.New()` の実装時に `PhoneNumbers` へこのプロバイダーを接続する。ロケール全体のテストと encli の結合検証でも、電話番号が表のいずれかの書式に一致することを確認する。

### EIN の対応範囲と未対応時の挙動

`Company().EIN() string` は、EIN 用の接頭辞データがある場合に、米国の Employer Identification Number の書式 `XX-XXXXXXX` に沿ったテストデータを生成する。v0.0.8 はデータがないと `-1234567` 型の値を返す。v0.0.9 では `EINPrefixes` が nil または空の場合に、空文字 `""` を返す。ロガーを設定している場合はロケール未対応の警告を出す。

- [ ] `pkg/faker/generator/company/company.go` の `EIN()` で、乱数を使う前に `len(c.data.EINPrefixes) == 0` を確認する。未対応なら `EIN()` から直接 `log.UnavailableLocale(1)` を 1 回呼び、空文字を返す。これにより呼び出し元が実際に使ったメソッド名がログに載る。対応時は既存の `EINPrefix()` と 7 桁の乱数生成を使う。
- [ ] `EIN()` の英語の GoDoc に米国向けであることと未対応時の挙動を明記する。文案は “EIN returns a synthetic U.S. Employer Identification Number in XX-XXXXXXX format. If the locale has no EIN prefix data, it returns an empty string and logs a warning when a logger is configured.”
- [ ] 既存の `company_test.go` で、`en_US` の出力全体が `^[0-9]{2}-[0-9]{7}$` に一致し、データを設定したカスタムロケールでも指定の接頭辞を使うことを確認する。`ja_JP` と新規 5 ロケールでは空文字を確認する。ロガーを一時設定したケースでは、`EIN()` のロケール未対応の警告が 1 件出ることを検査し、テスト後にロガーを解除する。同じシードの乱数源を 2 つ作り、一方で未対応の `EIN()` を呼んでも、その後の乱数出力がもう一方と一致することを検証する。`go test ./pkg/faker/generator/company` を実行する。

### 移行ガイドに掲載する手順

1. 開発・CI のツールチェーンを Go 1.26.4 以上にし、利用側モジュールで `go get github.com/ensoria/gofake@v0.0.9` を実行する。
2. `f.Rand.Num.IntBt(1, 10)` を `f.Num().IntBt(1, 10)` に、`f.Person.Name()` を `f.Person().Name()` に変更する。コア 6 カテゴリと既存 13 フィールドの対応表を載せる。`p := f.Person` のようにフィールドを値として取得するコードは `p := f.Person()` にする。`f.Person` 自体はメソッド値としてもコンパイルできるため、`any` への代入やコールバックはコンパイル結果に加えて期待型を確認する。[Go 言語仕様のメソッド値](https://go.dev/ref/spec#Method_values)
3. `Faker` のフィールドを初期化・再代入する箇所は用途ごとに書き換える。乱数の再現は `CreateWithSeed` / `CreateWithLocaleAndSeed`、任意の `*rand.Rand` や個別構成は `core.NewRand` と各生成器の `New`、シリアライズや反射で公開フィールドを読む用途は必要なデータを明示した構造体を使う。コピーした値も生成器は共有するため、独立した乱数列が必要な場合はコンストラクタから別のインスタンスを作る。
4. `*Faker` のメソッドを呼ぶ箇所ではポインタまたはアドレス取得可能な変数を使う。`map[string]faker.Faker` の要素・`faker.Faker` を値で返す関数の結果は、ローカル変数に取り出すかポインタで保持する。インターフェースにアクセサを要求する場合は `*faker.Faker` を渡す。encli の `Seed(faker.Faker)` では引数 `f` に対し `f.Person().Name()` のように呼ぶ。[Go 言語仕様の呼び出し](https://go.dev/ref/spec#Calls)
5. Ensoria で新ロケールを使う場合は、公開後の対応版の encli バイナリを用意し、利用プロジェクトの gofake も v0.0.9 へ上げる。利用側で encli モジュールを上げると Go の最小バージョン選択により gofake も上がる場合がある。`go list -m github.com/ensoria/gofake github.com/ensoria/encli` で選択版を確認し、`go mod tidy` と `go test ./...` を通す。固定シードのゴールデンデータを持つ利用者は、自分の呼び出し順と入力で差分を確認する。[Go の最小バージョン選択](https://go.dev/ref/mod#minimal-version-selection)
6. EIN 用のデータがないロケールで `EIN()` を呼ぶ箇所は、空文字を未提供として扱う。以前の `-1234567` 型の値に依存するアサーションを更新する。この呼び出しが乱数を消費しなくなるため、同じ Faker の後続出力を固定シードで比較している場合は、ゴールデンデータの差分を確認する。

## 4. encli の `seed --locale` 対応
